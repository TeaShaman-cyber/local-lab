# Патч: детерминированная нормализация GitHub-якорей перед retain

Патч к плагину Hindsight для Hermes. Задача — [local-lab#7](https://github.com/TeaShaman-cyber/local-lab/issues/7).

## Зачем

Recall возвращает факты с номерами issue без репозитория: «политика в issue #5» вместо `TeaShaman-cyber/local-lab#5`. Проверено 2026-10-30: правило в `retain_mission` применяется, но слабая модель извлечения (`upstage/solar-mini4:free`, p95 29 с) не склеивает репозиторий из соседнего предложения.

Решение: подставлять репозиторий **до** модели, детерминированно — regex плюс `git remote`.

## Что делает

1. Берёт `owner/repo` из `git remote get-url origin` рабочего каталога (кэш 300 с).
2. В тексте, уходящем в retain, заменяет `#NNN` на `owner/repo#NNN`.
3. Не трогает номера, у которых уже есть `owner/repo` перед `#`.
4. Если remote не определён — не меняет ничего.

## Документация Hindsight

- Сайт: <https://hindsight.vectorize.io/>
- Исходники: <https://github.com/vectorize-io/hindsight>
- Поля банка, использованные при проверке: `retain_mission`, `retain_extraction_mode` (значение `concise`), `retain_strategies` (не задано)

## Известное ограничение (найдено до ревью)

Замена агрессивна: `Версия #1 в тексте` → `Версия TeaShaman-cyber/local-lab#1`. Regex не отличает номер issue от номера версии или заголовка.

Варианты ужесточения, которые просим оценить:

- требовать контекстное слово рядом (`issue`, `PR`, `задача`, `pull`, `#` после `fix`/`close`);
- заменять только номера, встречающиеся в тексте вместе с `github.com` или уже известным репо;
- ограничить диапазон номеров (например, `#1` — это почти всегда не issue);
- оставить как есть и признать шум допустимым (тогда нужен замер, а не мнение).

## Что просим проверить

1. Логику regex: false positive и false negative на реальных текстах.
2. Поведение при `git remote` вида `git@github.com:owner/repo.git` и при отсутствии remote.
3. Кэш по `cwd`: не залипает ли репозиторий при смене проекта в одной сессии.
4. Потокобезопасность: retain может идти из другого потока.
5. Место вызова `_build_retain_item` — не пропускает ли он другие пути записи (`_retain_batch` вызывается ещё в нескольких местах).

## Границы

- `retain_mission` не меняется — он про язык и структуру фактов.
- Уже сохранённые факты не переписываются.
- В upstream (`vectorize-io/hindsight`) этот патч пока не отправлялся.

## Ревью Codex-бота (2026-10-30)

Три находки P2 приняты и исправлены в текущей ревизии патча:

| Находка | Исправление |
|---|---|
| `ssh://git@github.com:22/o/r.git` и `https://github.com:443/o/r.git` давали `None` | в шаблон добавлен необязательный порт `(?::\d+)?` |
| `https://notgithub.com/team/repo.git` давал `team/repo` | `github.com` якорится через `(?:^|[@/])`, подстрока больше не совпадает |
| HTML-сущность `&#123;` превращалась в `&owner/repo#123` | в lookbehind добавлен `&` |

Одна находка **не воспроизводится**: утверждалось, что URL с якорем `...?view=full#123` ломается. Проверено на строке: перед `#` стоит буква, lookbehind `[\w./&-]` запрещает замену, адрес сохраняется без изменений.

## Как применить и откатить

```bash
# применить
patch -p1 < patches/hindsight-anchor-normalize.patch

# откатить: удалить вызов в _build_retain_item
```

Перед правкой плагина делается копия `__init__.py.bak-*`.
