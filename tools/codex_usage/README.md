# codex-usage

Сборщик остатка лимитов подписки ChatGPT/Codex: пятичасовое окно и недельное.

Отвечает на вопрос **«сколько осталось»**, а не «сколько потрачено». Расход виден и так — по токенам в логах; остаток не был виден нигде, пока лимит не кончался посреди задачи.

## Откуда данные

`codex app-server`, метод `account/rateLimits/read` (JSON-RPC по stdio).

Официальный документированный путь. Недокументированный `wham/usage` не используется: правила OpenAI запрещают программное извлечение данных. Подробности и альтернативы — `docs/research/codex-usage-monitoring.md`, спека — `docs/specs/codex-usage-monitoring.md`.

## Запуск

```bash
python tools/codex_usage/codex_usage.py
```

Коды возврата:

```text
0   опубликовано
2   нет доступа (нет auth.json, нет токена)
3   нечего публиковать / источник не дал данных
4   публикация в Loki не удалась
```

Расписание — Windows Task Scheduler, раз в 5 минут. Не через Hermes: мониторинг не должен зависеть от того, что мониторит.

## Что публикуется

Стрим Loki: `service_name=openai-codex`, `log_type=subscription`, `job=codex-usage`.

```text
codex_session_used_percent         5-часовое окно, % использовано
codex_session_remaining_percent    производное: 100 - used
codex_session_reset_unix           когда сбрасывается (epoch)
codex_session_window_minutes       длина окна (300) — проверка, что окно то же
codex_weekly_*                     то же для недельного (10080 минут)
codex_credits_balance              остаток докупленных кредитов
codex_credits_has                  0/1
codex_plan                         value=1, план как label (plus/pro/…)
codex_limit_reached                0/1
codex_reset_credits_available      доступные reset-кредиты
```

Панель читает через LogQL: `{service_name="openai-codex"} | logfmt | unwrap value`.

Проверка, что строки дошли:

```logql
{service_name="openai-codex"} |= "codex_"
```

## Три решения, которые легко сломать

**Окна определяются по `windowDurationMins`, а не по позиции.** `primary`/`secondary` — имена полей, а не смысл: 300 минут — пятичасовое окно, 10080 — недельное. Если провайдер поменяет порядок, сборщик это заметит, а не подпишет недельный лимит как сессионный.

**`credits.balance` приходит строкой** (`"0"`). Без приведения к числу `unwrap` в LogQL вернёт пустоту, и панель покажет «нет данных» вместо нуля — что читается как «неизвестно».

**Отсутствие данных — не ноль.** Нет окна, нет доступа, пустая публикация — это отказ с кодом, а не строка `value=0`. Ноль на графике означает «лимит свободен», и это ложь.

## Ограничение интерпретации

Лимит **общий для аккаунта**. Codex-бот ревьюит pull request в облаке, второй агент работает по GitOps в других репозиториях — их вызовы идут в тот же лимит и локально не видны.

Поэтому панель не отвечает на вопрос «кто потратил». Любая корреляция «локальная активность ↔ расход» неполна и не должна становиться алертом.

## Тесты

```bash
uv run --no-project --with pytest python -m pytest -q tools/codex_usage
```

16 тестов: преобразование снимка в метрики, маппинг окон, строковый баланс, отказы, публикация. Живой вызов app-server и запись в Loki — ручная проверка, в CI не воспроизводятся.
