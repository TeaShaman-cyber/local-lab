# Mutation testing

Проверка не того, что тесты проходят, а того, что они **падают**, когда код
ломается. Обычный прогон этого не показывает: тест может быть зелёным и при
живом дефекте — в этом репозитории такой случай уже был (throttle в
`recall_mcp_hook` ходил в сеть, тест этого не замечал).

## Что мутируем

Один файл: `tools/honcho/recall_mcp_hook.py`. Тест лежит рядом, но в
`module-path` не входит — cosmic-ray мутирует всё, на что его указали, и тесты
мутировать нельзя.

## Как это устроено

266 мутантов на текущий файл. Один поток — около 40 минут, поэтому прогон
режется на 16 шардов: каждый job делает `init`, удаляет чужие work items
(`rowid % 16`), исполняет свои и публикует `shard-result.json`.

Шардирование воспроизводимо: `init` вставляет строки в одном и том же порядке
для одного дерева и одной версии cosmic-ray, а версия закреплена в workflow.

## Почему это не «зелёный гейт»

Отчёт различает два состояния, и оба — провал:

- артефакта шарда нет — job умер, ничего не измерив;
- `missing > 0` — job отработал, но не по всем своим мутантам.

Считать такое «нулевым числом выживших» — известный способ получить зелёный
гейт над невыполненной работой. `report.py` падает при `missing > 0`,
`aggregate.py` падает при отсутствующем шарде.

Порог по выжившим по умолчанию отключён (`-1`): первый прогон должен показать
картину, а не покраснеть на ровном месте.

## Запуск

```bash
# вручную, с порогом
gh workflow run mutation -f max_survivors=0

# локально, один шард
docker run --rm -v "$PWD:/repo" -w /repo python:3.12-slim bash -lc '
  pip install -q "cosmic-ray==8.8.0" pytest
  python -m pytest tools/honcho/test_recall_mcp_hook.py -q
  cosmic-ray init mutation/cr.toml session.sqlite
  python mutation/shard.py session.sqlite 0 16
  cosmic-ray exec mutation/cr.toml session.sqlite
  python mutation/report.py session.sqlite'
```

## Границы

- Это аудит, а не гейт на каждый коммит: запуск по кнопке и по расписанию.
- In-process рефакторинг тестов не требуется: cosmic-ray мутирует файл и
  запускает команду тестов как есть, `mutmut` для этого не подходит — ему нужен
  импорт модуля тестами.
- Выжившие мутанты не исправляются автоматически: сначала смотрим список, потом
  решаем, тест это или мёртвый код.
