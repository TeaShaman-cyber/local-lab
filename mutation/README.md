# Mutation testing

Проверка не того, что тесты проходят, а того, что они **падают**, когда код
ломается. Обычный прогон этого не показывает: тест может быть зелёным и при
живом дефекте — в этом репозитории такой случай уже был (throttle в
`recall_mcp_hook` ходил в сеть, тест этого не замечал).

## Что мутируем

Один файл: `tools/honcho/recall_mcp_hook.py`. Тест лежит рядом, но в
`module-path` не входит — cosmic-ray мутирует всё, на что его указали, и тесты
мутировать нельзя.

## Как это устроено

Количество мутаций зависит от проверяемого дерева (266 — исторический baseline, в другом merge-ref их может быть больше). Один поток — около 40 минут, поэтому прогон
режется на 16 шардов: каждый job делает `init`, удаляет чужие work items
(`(rowid - 1) % 16` переводит однобазовый SQLite `rowid` в номер шарда 0–15),
исполняет свои и публикует `shard-result.json`.

Шардирование воспроизводимо: `init` вставляет строки в одном и том же порядке
для одного дерева и одной версии cosmic-ray, а версия закреплена в workflow.

## Почему это не «зелёный гейт»

Отчёт различает три состояния, и все означают провал измерения:

- артефакта шарда нет — job умер, ничего не измерив;
- `unmeasured > 0` — job отработал, но не по всем своим мутантам. Сюда входят
  `worker_outcome != NORMAL`, результат без соответствующей mutation spec и
  `test_outcome=INCOMPETENT`: в последнем случае cosmic-ray поймал сбой запуска
  тестового процесса и всё равно сохранил строку с нормальным воркером, хотя
  тест против мутанта не запускался;
- stable fingerprints пересекаются, оставляют gap или принадлежат разным
  manifest — независимые `init` не разделили одно и то же множество мутаций.

`job_id` для этой проверки не годится: Cosmic Ray создаёт новый случайный UUID
при каждом `init`. `report.py` вычисляет SHA-256 полной mutation spec без
`job_id`, а затем digest полного manifest до шардирования. Поэтому aggregate
может доказать общий источник, отсутствие пересечений и полный union.

Считать неполную работу «нулевым числом выживших» — известный способ получить
зелёный гейт над невыполненной работой. `report.py` падает при `unmeasured > 0`,
`aggregate.py` — при любой из трёх структурных ошибок.

Порог по выжившим по умолчанию отключён (`-1`): первый прогон должен показать
картину, а не покраснеть на ровном месте.

## Запуск

Локально — только на копии. cosmic-ray пишет мутации в рабочее дерево и при
прерывании не откатывает их: прерванный прогон уже оставил в
`recall_mcp_hook.py` строку `str ** None` вместо `str | None`.

```bash
# вручную, с порогом
gh workflow run mutation -f max_survivors=0

# локально, один шард, на копии (монтирование только для чтения)
docker run --rm -v "$PWD:/repo:ro" -w /tmp python:3.12-slim bash -lc '
  pip install -q "cosmic-ray==8.8.0" "pytest==9.2.0"
  cp -r /repo /tmp/work && cd /tmp/work
  python -m pytest tools/honcho/test_recall_mcp_hook.py -q
  cosmic-ray init mutation/cr.toml session.sqlite
  python mutation/shard.py session.sqlite 0 16
  cosmic-ray exec mutation/cr.toml session.sqlite
  python mutation/report.py session.sqlite \
    --source-commit "$(git rev-parse HEAD)" \
    --source-tree "$(git rev-parse HEAD^{tree})" \
    --run-url "https://github.com/TeaShaman-cyber/local-lab/actions/runs/0"'
```


## Доказательства для PostHog Scout

Поле source_commit_sha — точный commit, который проверял runner, а
source_tree_sha — его Git tree. Их сохраняют **до** запуска Cosmic Ray.
Для pull_request это обычно синтетический merge-ref, а не PR head SHA.
Агрегатор запрещает объединять разные commits, tree SHA или workflow run URL.

Каждый surviving mutant теперь имеет каноническую полную spec (без случайного
job_id), stable mutation_id, untruncated diff и исход теста/воркера.
Эти данные пригодны для последующей проверки контракта Scout; одни лишь
цифры GitHub CI и фрагменты идентификаторов такой проверки не заменяют.

Артефакты GitHub остаются источником; их наличие не доказывает, что
PostHog Scout может их прочесть. Scout пока выключен. Локальные
измерения не становятся CI-evidence от подстановки чужого workflow URL.

## Границы

- Это аудит, а не обязательный порог качества на каждый коммит: запуск по
  кнопке, по расписанию и на релевантных PR (`mutation/**`, workflow, сам
  мутируемый hook или его тесты). PR-проверка гарантирует исправность измерителя
  и свежий baseline, но не падает из-за числа survivors, пока порог равен `-1`.
- In-process рефакторинг тестов не требуется: cosmic-ray мутирует файл и
  запускает команду тестов как есть, `mutmut` для этого не подходит — ему нужен
  импорт модуля тестами.
- Выжившие мутанты не исправляются автоматически: сначала смотрим список, потом
  решаем, тест это или мёртвый код.
