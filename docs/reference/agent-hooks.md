# Хуки плагинов Hermes: что реально умеет `pre_tool_call`

Дополнение к upstream-документации (`hermes-agent/references/agent-hook-plugins.md`),
которая описывает только `action: "block"`. Здесь — то, что проверено чтением кода
Hermes v0.22.5, с указанием мест, где это лежит. Upstream не копируется: копия
стареет молча, оригинал читается в профиле.

## Три действия, а не одно

`pre_tool_call` может вернуть директиву. В коде разбираются **три**:

| `action` | Что делает | Поля |
|---|---|---|
| `block` | запрещает вызов, сообщение становится результатом инструмента | `message` |
| `approve` | эскалирует вызов на подтверждение человеком | `message`, `rule_key` (гранулярность `[a]lways`) |
| `modify` | подменяет аргументы до вызова | `args` (частичный dict) |

Источник: `hermes_cli/plugins.py`, датакласс `_PreToolCallDirective` и функция
`_get_pre_tool_call_directive_details`; применение — `agent/tool_executor.py:683` и
`agent/agent_runtime_helpers.py:2501`.

## Приоритет

`block` > `approve` > нет директивы, **независимо от порядка регистрации плагинов**.
Любой валидный veto побеждает ранее зарегистрированный запрос на подтверждение;
среди `approve` выигрывает первый валидный.

## `modify`: как именно

```python
if action == "modify":
    partial = result.get("args")          # частичный словарь
    if isinstance(partial, dict) and partial:
        modified_args = {**накопленное, **partial}
```

Три следствия, каждое важно:

1. **Shallow merge, не замена.** Передавать надо только изменяемые ключи; остальные
   аргументы сохраняются. `{"args": {"char_limit": 30000}}` не сотрёт `urls`.
2. **Накопление между плагинами.** Каждый `modify` мержится в общий словарь,
   построенный из исходных аргументов. Два плагина могут править разные ключи.
3. **`modify` обрабатывается раньше гейта** `block`/`approve`. Модификация видна,
   даже если другой плагин затем блокирует вызов — то есть порядок «кто прав» не
   зависит от того, кто вернул директиву первым.

Пустой или не-словарный `args` игнорируется: `modify` без полезной нагрузки — no-op,
а не ошибка.

## Почему это важнее, чем кажется

Правило в скилле — совет: оно работает, пока агент его помнит. Хук — механизм:
он срабатывает независимо от того, вспомнил ли агент.

Пример из практики (2026-09): агент девять раз из десяти передавал `char_limit`
вдвое-втрое ниже дефолта и терял 97% документации. Запись в скилл это не
останавливает — она объясняет. `modify` останавливает: аргумент правится до вызова,
независимо от намерения агента.

## Что проверить перед тем, как на это опираться

- `pre_command` в v1 — **observer-only**: директивы игнорируются, rewrite обещан
  отдельной middleware-веткой (`#64204/#64231`). Не путать с `pre_tool_call`.
- Хук видит аргументы **после** нормализации, но **до** валидации инструментом: если
  подменить значение на недопустимое, ошибку вернёт сам инструмент.
- `rule_key` в `approve` определяет гранулярность «больше не спрашивать». Один и тот
  же ключ для разных инструментов склеит их в одно разрешение — давать разные.
