# Методика замера качества памяти

Как измерить, стало ли извлечение фактов и поиск по памяти лучше или хуже. Без этого документа любой тюнинг — вера.

**Связанные issue:** #33 (модели извлечения), #108 (golden set поиска), #121 (размер профиля), #122 (бэкап кэша).

## Две разные вещи, которые нельзя смешивать

| | что меряем | чем | issue |
|---|---|---|---|
| **retain** | качество извлечения фактов моделью | текст → факты, precision/recall | #33 |
| **recall** | качество поиска по готовой памяти | golden set, hit@k и позиция | #108 |

Это разные замеры. Гонять recall и делать вывод о модели извлечения — ошибка, которая уже была.

## Чеклист перед замером

- [ ] **Цель замера названа.** «Стало ли лучше» без «по сравнению с чем» — не замер.
- [ ] **Стенд поднят и это он, а не прод.** Навык `hindsight-operations`: прод запрещён как цель замера, разрешён только для read-only аудита.
- [ ] **Версия на стенде совпадает с продом** (`ghcr.io/vectorize-io/hindsight:1.1.0`).
- [ ] **Патчи учтены.** Все пять патчей живут в **плагине Hermes**, а не в сервере: `anchor-fallback`, `anchor-normalize`, `recall-dates`, `reflect-budget`, `retain-noise-filter`. Стенд — только сервер, поэтому поведение плагина надо **эмулировать** (см. ниже).
- [ ] **Модель, которую меряем, совпадает с прод-моделью** на той же роли.
- [ ] **Язык тот же**, что в проде: банк русский, `HINDSIGHT_API_LLM_OUTPUT_LANGUAGE=ru`.
- [ ] **Инструкция разметки заморожена.** Менять её после начала разметки нельзя — прогоны станут несравнимы.
- [ ] **Baseline записан** комментарием в issue с датой и коммитом.

## Эмуляция плагина: обязательна

Плагин — фронтенд: он **до отправки** фильтрует шум, нормализует GitHub-ссылки и ставит timestamp. Мерить сервер без этих шагов значит мерить другую систему.

Что воспроизводить (`plugins/hindsight/__init__.py`):

```text
_RETAIN_NOISE_RE        отбрасывает строки «фоновый процесс proc_X завершился нормально»
_RETAIN_ERROR_RE        сохраняет такие строки, если в них есть признак ошибки
_NOISE_PATTERNS_FILE    пользовательские шаблоны, одна регулярка на строку
_normalize_github_refs  owner/repo#N вместо голого #N
_event_timestamp        ISO-таймстемп на каждый item
metadata                message_count, turn_index
```

Готовый эмулятор: `plugin_emulate.py` (в scratch, переносится в `tools/eval/` при первом коммите замера).

**Проверка эмуляции:** на корпусе без process chatter фильтр не отбрасывает ничего — это ожидаемо. Если отбрасывает, значит паттерны шире, чем кажется, и это надо увидеть.

## Отбор корпуса

Правила, каждое с причиной:

```text
6–10 подряд идущих сообщений одного треда   retention видит ход, а не реплику
есть цифры (>= 15 символов-цифр)            там модели ломаются: 6.27 vs 23.8
есть слово-решение (решено/оказалось/...)   факт, который стоит помнить
250–600 слов                                несколько фактов, но размечаемо руками
не больше 2 фрагментов на сессию            корпус не перекошен одной темой
текущая сессия исключена                    иначе размечаешь свой же текст
```

**Не синтетика.** Синтетический текст уже давал сдвиг: 4.62 вместо 6.27 на реранкере.

Корпус лежит в `.hermes/eval/` — вне git, потому что это реальные тексты переписки. В репозиторий идут методика и результаты, не содержимое.

## Разметка: три модели, три семейства

Один разметчик даёт «gold есть». Три показывают, где gold спорный.

| роль | модель | источник оплаты |
|---|---|---|
| A | `gpt-6-luna` | Codex-подписка |
| B | `gemini-2.5-flash` | BotHub caps |
| C | `deepseek-chat-v3.1` | BotHub caps |

**Исключены:** `claude-fable-5*` (жжёт баланс), `gpt-6-astra*` (5-часовой лимит).

Вызов: без инструментов (`hermes -z ... -t ""` для Codex, обычный API для остальных). Разметчик с tool-loop тратит подписку на попытки что-то проверить вместо разметки.

**Цена:** одна разметка ≈ $0.001, корпус 8 фрагментов × 2 модели ≈ $0.014.

### Определения типов — брать из апстрима, не из головы

`vectorize-io/hindsight`, `engine/retain/fact_extraction.py`:

```text
world      о пользователе, системе, правилах, предпочтениях.
           ОСТАЁТСЯ world, даже если сказано в диалоге с ассистентом.
experience действие САМОГО ассистента: сделал, решил, рекомендовал.
observation НЕ тип факта — слой убеждений из консолидации.
```

Решающее правило: **кто субъект утверждения.** Пользователь сообщает факт о системе → `world`.

Инструкция v2: `annotate-instruction-v2.md`.

## Ловушки формата ответа

| модель | ловушка | обход |
|---|---|---|
| `gemini-2.5-flash` | ```json фенс + обрезка при `max_tokens=2000` | снять фенс, лимит ≥ 6000 |
| `gpt-6-luna` | токен `</|im_end|>` внутри JSON | обрезать по последней `}` |
| `deepseek-chat-v3.1` | чисто | — |

**Лимит вывода на разметке не меньше 6000.** Разметка — список фактов, а не короткий ответ.

## Сведение в gold

Правило: **делим по совпадению, а не по количеству.** Разное число фактов у моделей не мешает — сопоставляем отдельные факты, не списки.

```text
нашли все три   → gold, высокое доверие
нашли двое      → gold «2/3», спорный
нашёл один      → кандидат, в gold не идёт без проверки
```

### Сравнение: три уровня, от дешёвого к дорогому

```text
1. совпадение набора чисел (непустого)  → один факт, дальше не проверяем
2. Jaccard по значимым словам >= 0.6
3. локальный эмбеддинг >= 0.82          (paraphrase-multilingual-MiniLM-L12-v2)
```

**Почему не только Jaccard.** «Реранк занимает 6.27 с» и «замер реранкера дал 6.27 секунды» — один факт, но слова разные. Числа переживают переформулировку, слова нет. Измерено: фрагмент с плотными техническими фактами дал 83% согласия по Jaccard, фрагмент с обсуждением трактовок — 11%.

**Пороги — стартовая точка, не истина.** Калибровать по первому прогону.

## Метрики

Для retain:

```text
precision = matches / (matches + mismatches + hallucinations)
recall    = matches / (matches + mismatches + omissions)
```

Четыре статуса на факт: match, mismatch, **omission** (в gold есть, извлечено нет), **hallucination** (извлечено, в gold нет).

Для recall: `hit@k`, позиция первого попадания, `precision`, `abstain_passed/total`, `active_total`.

**LLM-судью не использовать.** «Verify with Caution» (ACL 2025): судьи расходятся между собой и смещены против парафразов — а парафраз один из наших видов кейсов.

## Чего ждать от чисел

- **Разброс между моделями** — норма. 19 / 34 / 43 факта на одном тексте.
- **Разброс — результат, а не помеха.** Он показывает, где корпус неоднозначен.
- **«Дыра в эталоне» выглядит как галлюцинация.** В клиническом extraction-пайплайне 54% кажущихся false positives оказались дырами разметки. Прежде чем говорить «модель выдумала», проверить gold.

## Запись результата

- **В issue, не в чат.** Один комментарий на слой находок, с датой и цифрами.
- **Baseline фиксируется** первым прогоном; последующие сравниваются с ним.
- **Отрицательный результат — тоже результат.** «Модели не различаются» пишется так же, как «различаются».

## Открытые вопросы

- Сколько фрагментов нужно, чтобы различить модели с разницей в пару процентов. Литература: 15–30 для регрессии, 50 для baseline, 168 для продакшена.
- Порог abstain: пустая выдача на содержательный вопрос — pass или провал. Решается флагом `answerable` в кейсе.
- Нужен ли прогон с `LLM_OUTPUT_LANGUAGE=en` для сравнения языков. Отложено: сначала baseline в прод-конфигурации.
