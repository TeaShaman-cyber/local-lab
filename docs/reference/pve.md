# PVE T490 — лабораторный гипервизор

Единственное место, где описано, как обращаться с PVE. Артефакты лежат рядом:

| Что | Где |
|---|---|
| Runbook установки | [`proxmox-t490-native-install.md`](proxmox-t490-native-install.md) |
| Снимок конфигурации (31 файл) | [`config/`](config/) — сеть, fstab, sysctl, systemd, LXC, Alloy |
| Сборщик снимка | `tools/pve_config/collect.sh` |
| Запись в реестре | `infra/registry.yaml` → `LAB-001` |

## Идентификация

```text
host        pve-t490 (pve.lab)
address     10.67.163.198
version     Proxmox VE 9.2.24, kernel 7.0.14-26-pve
role        стенд №1 для тестов и экспериментов (приоритет 1)
```

## Как проверить, что он жив

```bash
curl -sk -o /dev/null -w '%{http_code}\n' https://10.67.163.198:8006/   # 200 = веб жив
ssh root@pve.lab 'pct list'                                            # список контейнеров
```

**Ping не является проверкой.** ICMP на этом хосте не отвечает: `ping 10.67.163.198`
даёт 100% потерь при полностью рабочем сервере. Проверено 2026-10-30 — сначала
именно из-за этого PVE был ошибочно записан как выключенный.

API без токена отвечает `401` — это нормально, а не поломка.

## Мониторинг

| Сигнал | Источник |
|---|---|
| Хост | Grafana Cloud, `job="integrations/unix"`, `host="pve-t490"`, `instance="pve.lab"` |
| Дашборд | `https://tealaphid71.grafana.net/d/pve-t490-host` — CPU, память, load, `/`, Wi-Fi, uptime |
| Логи LXC | Alloy на хосте → Grafana Cloud |

Прямого `node_exporter` (9100) и `pve-exporter` (9221) на хосте нет — метрики идут
через интеграцию Alloy. Поэтому поиск по IP в Prometheus ничего не находит:
искать надо по `host="pve-t490"`.

## Железо и главное ограничение

```text
RAM        7.48 GiB физически, swap отсутствует
CPU        ThinkPad T490, слабый
диск       /dev/sda4 ext4 79G, Windows живёт в dual-boot
```

**Память — узкое место, а не диск и не CPU.** Наблюдалось два global OOM при
загрузке моделей Hindsight: ядро убивало процесс при RSS около 1.60 и 1.75 GiB,
потому что свободной памяти хоста было около 1.16 GiB. Это **не** достижение
лимита контейнера: CT ограничен 3 GiB, а падал весь хост.

Практика: не запускать одновременно две модели в памяти, проверять доступную RAM
до старта, помнить, что 8 ГБ — это память хоста целиком, а не стенда.

## Сеть и гости

```text
wlp5s0        статический адрес
vmbr0         10.10.10.1/24 — внутренняя сеть для гостей
LXC 100       vpn-gw 10.10.10.2 — AmneziaWG наружу, dnsmasq для гостей
LXC 101       test-gw — проверено, ходит через VPN
CT103         hindsight-stand (production не трогает)
CT104         Cognee
```

Гостям выдаётся `gateway 10.10.10.2`, `dns 10.10.10.2`.

## Грабли, уже собранные

| Симптом | Причина | Что делать |
|---|---|---|
| `ping` не проходит | ICMP закрыт | проверять HTTP 8006 и `ssh` |
| `curl /api2/json/*` → 401 | нужен тикет/токен | для проверки живости хватает `/` → 200 |
| В Grafana нет метрик по IP | метки `host`/`instance`, не IP | искать `host="pve-t490"` |
| Модель убита при старте | свободная RAM хоста | освободить память, не запускать две модели |
| Стенд «пропал» после перезагрузки ноутбука | dual-boot: загружена Windows | загрузить PVE |

## Что важно соблюдать

- PVE — тестовый стенд. Продовая работа (Hindsight на ноутбуке, мониторинг, бэкап) идёт на `LAB-002`; на PVE её не переносить без отдельного решения.
- Изменения конфигурации хоста фиксировать в снимке: `tools/pve_config/collect.sh`, затем коммит — иначе конфиг снова начнёт жить только на диске.
- Секреты в снимок не попадают: сборщик падает, если находит ключ.
