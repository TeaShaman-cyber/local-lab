# Triage Labels

The skills speak in terms of canonical triage roles. This file maps those roles to
the actual label strings used in this repo's issue tracker, and records the parts of
the skill contract that are easy to miss.

## State roles — exactly one per issue

| Label in mattpocock/skills | Label in our tracker | Meaning                                  |
| -------------------------- | -------------------- | ---------------------------------------- |
| `needs-triage`             | `needs-triage`       | Maintainer needs to evaluate this issue  |
| `needs-info`               | `needs-info`         | Waiting on reporter for more information |
| `ready-for-agent`          | `ready-for-agent`    | Fully specified, ready for an AFK agent  |
| `ready-for-human`          | `ready-for-human`    | Requires human implementation            |
| `wontfix`                  | `wontfix`            | Will not be actioned                     |

## Category roles — exactly one per issue

| Label in mattpocock/skills | Label in our tracker | Meaning                   |
| -------------------------- | -------------------- | ------------------------- |
| `bug`                      | `bug`                | Something is broken       |
| `enhancement`              | `enhancement`        | New feature or improvement |

**A triaged issue carries exactly one category and exactly one state.** Missing the
category is the failure this file previously allowed: the `triage` skill requires
both, so an issue with only a state label looks triaged and is not.

If two state labels end up on one issue, that is a contradiction — flag it and ask
before acting, do not pick one silently.

## Disclaimer on triage comments

Every comment posted by triage **must** open with:

```
> *This was generated by AI during triage.*
```

This is part of the skill contract, not a courtesy: a reader has to be able to tell
an automated triage note from a human decision without checking the author.

## Relation to the Project board

Three vocabularies describe one issue, and they are not equal:

| Surface | Role |
|---|---|
| **Labels** (this file) | **source of truth** for category and state |
| Project #19 `Status` | projection for the board — convenient, derived, may lag |
| `criticality` (P1/P2) in `infra/registry.yaml` | change class per `RULE-011`; orthogonal to triage state |

When the board and the labels disagree, the labels win and the board is corrected.
A board status is not evidence that an issue was triaged; it is a view.

## When a skill mentions a role

Use the corresponding label string from the tables above. If a skill asks for a role
that has no mapping here, stop and ask rather than inventing a label — an invented
label is invisible to every checker we have.
