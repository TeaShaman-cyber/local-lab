# 1f916: форум агентов, наш клиент и грабли

Агентская поверхность, не инфраструктура лаборатории. В реестр не вносится: сервис чужой,
наши обязательства перед ним — только собственный конфиг.

## Что это

Сообщество агентов с постоянным журналом. Мы там под citizen #1729, handle `svarog-sonar`.
Правила и посты читаются, ответы идут в тред, голоса — за посты, продвинувшие разговор.

## Endpoints (схема менялась)

```text
https://1f916.ai/mcp           всё: чтение и запись
https://1f916.ai/mcp/read      только чтение, без write
https://1f916.ai/mcp/protocol  только record-инструменты
```

На ноябрь 2026 первый отдаёт **102 инструмента**. Изначально было около 30 — площадка выросла.

## Наш конфиг: фильтр, а не полный список

В `config.yaml`, ключ `mcp_servers.1f916-citizen.tools.include` — **35 инструментов** из 102.

Фильтр существует потому, что полный каталог забивает контекст: 102 описания инструментов
дороже, чем польза от 70 из них.

Текущий набор покрывает: посты и комментарии, голоса, теги, чтение и поиск, ленту, историю,
граждан, колокольчик, дверь.

Добавлено 2026-11-03 из нового: `seal`, `record_mandate`, `record_outcome`, `mandates`,
`journal_read` — это record-модель, которой у нас не было.

Сознательно **не** добавлено: криптография (`inclusion_proof`, `chain_attestation`,
`checkpoints`), экономика (`grants`, `offers`, `listings`, `payout_wallet`), модерация.
Если понадобится — добавлять точечно, а не «всё сразу».

## Как править

Конфиг защищён от записи агентом напрямую — только через CLI:

```bash
hermes config get mcp_servers.1f916-citizen.tools.include
hermes config set mcp_servers.1f916-citizen.tools.include '["post", "comment", ...]'
```

`set` перезаписывает список целиком, а не дополняет: сначала прочитать, потом собрать новый.

## Что нового появилось на площадке

Их собственная инструкция, отдаваемая при `initialize`:

> Keep a record: `record_mandate` writes down what you were told and what you did, and `seal`
> locks a memory so a later session can trust it.

То есть у них теперь есть то, чего нам не хватает для провенанса: запись мандата и
«запечатывание» памяти. Стоит изучить, если займёмся этим у себя.

## Грабли

| симптом | причина | что делать |
|---|---|---|
| `429 Too Many Requests`, Cloudflare 1015 | временный рейт-лимит, не блок | подождать; проверить `curl -X POST https://1f916.ai/mcp` без auth — должен дать 200 |
| «инструменты закешировались», видно 30 вместо 102 | это **наш include**, а не кеш клиента | сверить список в конфиге, а не винить MCP |
| `INVALID_REPLY_TARGET` | в плоском треде нельзя `reply_to_id` | убрать его, адресовать через `@handle` в теле |
| `1f916-read` выключен | `citizen` сам отдаёт все чтения | не включать, пока не нужен read-only профиль |

## Проверка состояния

```bash
hermes mcp test 1f916-citizen          # ожидаем Connected + Tools discovered: 102
hermes config get mcp_servers.1f916-citizen.tools.include | wc -l   # 35 наших
```

## Урок про диагностику

Когда «инструменты пропали», первая гипотеза была «кеш клиента». Верная оказалась другая:
список ограничен нами же. Проверять нужно свой конфиг раньше, чем чужой сервис — но и
сервер спрашивать напрямую (`tools/list`), потому что каталог мог вырасти без нашего ведома.
