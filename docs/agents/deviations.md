# Отличия от скиллпака

Базовый шаблон — `mattpocock/skills`. Этот файл перечисляет **только отличия** от
него, каждое с причиной и ссылкой на issue. Всё, чего здесь нет, действует как в
шаблоне.

Правило: отличие без обоснования — это дрейф. Отличие без issue — это забывчивость.
Если отличие перестаёт быть нужным, оно убирается отсюда, а не обрастает оговорками.

## Как читать

1. Сначала шаблон: скиллы `triage`, `implement`, `code-review`, `to-spec`,
   `to-tickets`, `ask-matt` работают так, как написано в них.
2. Потом этот файл: здесь перечислено, что мы делаем иначе и почему.
3. Если правило есть в шаблоне, а здесь не упомянуто — оно действует без изменений.

## Версия скиллпака

Шаблон версионируется семантически (`package.json` + `CHANGELOG.md` в upstream),
поэтому версия фиксируется числом, а не датой.

| Параметр | Значение |
|---|---|
| Источник | `mattpocock/skills`, ветка `main` |
| **Версия установленной копии** | **1.3.2** (коммит `a496f55`, 2026-10-29) |
| **Версия upstream на 31.10** | **1.3.2** — копия актуальна |
| Скиллов установлено | **27 из 38** — выборочно, не все |
| Отклонений от шаблона | **8** (таблица выше) |
| `sha256` всех файлов копии (81) | `04c964d1d3ef1545badc3b7fc609d3bbb36fa7a92468071c0c66ef05f5efd3a4` |
| `sha256` только `SKILL.md` (27) | `4cf242d6a59fa6f51708c98d011c1aac669b59182c903234927ae7de12df0439` |

Два хеша, потому что одного мало: хеш по `SKILL.md` отвечает на вопрос «не разошлись ли
инструкции», но **не видит** правку reference-файла — а отклонения №7 и №8 добавляют
именно их. Полный хеш ловит любое изменение в копии, хеш по `SKILL.md` — только то,
что читает модель первой. Расхождение между ними означает «правлен reference-файл».

### Обновлено до 1.3.2 (31.10.2026)

Семь скиллов были на 1.3.1 и обновлены до 1.3.2:

`code-review`, `grilling`, `implement-spec`, `improve-codebase-architecture`,
`research`, `setup-matt-pocock-skills`, `wayfinder`.

Что изменилось по существу:

- **`code-review`** — субагенты запускаются с чистым контекстом, а не форком;
- **`setup-matt-pocock-skills`** — миграция `CONTEXT.md` → `GLOSSARY.md`, новый
  `issue-tracker-local.md` и каталог `agents/`;
- **`implement-spec`** — свежий исполнитель на каждый тикет.

Обновление заменяет каталог скилла **целиком**: старые reference-файлы не переживают
замену, поэтому «дописать поверх» здесь нельзя. Наши отклонения №7 и №8 не
затрагивались — upstream эти два файла не менял, и проверка трёхсторонней сверки это
подтвердила до обновления.

**Ошибка, которую это обновление вскрыло.** Первая версия скрипта обновления
вычисляла путь внутри скилла как «убрать имя из пути», и файлы ложились в
`<name>/<category>/SKILL.md`, а старый `SKILL.md` оставался на месте. Счётчик
записанных файлов при этом совпадал с ожидаемым, `find` находил 27 `SKILL.md` — и
всё выглядело успешным, хотя ни один скилл не обновился. Поймано только сверкой
`tools/dev/skillpack`, которая показала `skills 20` вместо 27.

Правило отсюда: считать записанные файлы недостаточно — надо проверять **путь**, по
которому они легли. Скрипт теперь падает, если `<name>/SKILL.md` отсутствует после
записи.

### Наши правки (не отставание)

Два скилла отличаются **не** потому, что upstream ушёл вперёд, а потому, что мы их
правили: `diagnosing-bugs` и `writing-for-agents` — см. отличия №7 и №8. Их хеши в

### Как отличать одно от другого

Разница в хеше не говорит, кто её внёс. Трёхсторонняя сверка с базовой линией:

```bash
cd /e/matt-upstream
# 5beb35b — коммит, с которого снята копия (версия 1.3.1)
git diff --name-only 5beb35b origin/main -- skills   # что менял upstream
# затем по каждому скиллу: installed == 5beb35b → мы не трогали;
#                           installed != 5beb35b → наша правка;
#                           installed != 5beb35b И upstream != 5beb35b → конфликт
```

Односторонняя проверка (только «наш хеш против upstream») смешивает два разных
события и приводит к неверному выводу «мы убрали требование», когда требование
только что добавлено на той стороне.

### Проверка свежести

Одна команда, без археологии:

```bash
python tools/dev/skillpack          # отчёт, rc=1 при дрейфе
python tools/dev/skillpack --json   # для скриптов
python tools/dev/skillpack --self-test
```

Что она различает:

| Вердикт | Значение | Что делать |
|---|---|---|
| `unchanged` | upstream не двигал, мы не трогали | ничего |
| `stale` | upstream ушёл вперёд | оценить diff, обновить или записать отличие |
| `our-edit` | правили мы, upstream не менял | должно быть в таблице отличий |
| `conflict` | правили обе стороны | разбирать руками |
| `up-to-date` | уже обновлён | ничего |

Инструмент требует локальный клон upstream (`E:/matt-upstream`) и сравнивает
трёхсторонне с `BASE_COMMIT`. Без клона он возвращает `rc=2`, а не «всё хорошо»:
отсутствие возможности сравнить — не доказательство совпадения.

Ручные команды больше не нужны: `find | sort | xargs cat | sha256sum` на Windows
даёт другой хеш, чем на Linux (порядок путей), поэтому он не воспроизводим между
машинами. Инструмент сортирует по относительному POSIX-пути сам.

**Граница:** обновление копии не означает принятие её поведения. Отличия остаются
в этом файле.

## Что мы **не** меняем

Эти части взяты как есть, и менять их нужно через issue с обоснованием:

- пять состояний триажа и их имена (`needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`);
- дисклеймер `> *This was generated by AI during triage.*` в каждом комментарии триажа;
- single-context раскладка домена (`GLOSSARY.md` и `docs/adr/` в корне);
- issue tracker — GitHub Issues через `gh` для записи.

## Проверка

Расхождение между этим файлом и реальным поведением — дефект. Проверяется глазами
при каждом изменении контракта; детерминированно не проверяется, потому что «что
считать отличием» — суждение, а не строка.
